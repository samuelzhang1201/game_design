> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the five policy actions into 17 data-driven laws decreed by courier, with a laws screen, per-province economy settlement and twelve military laws that carry effects.

**Architecture:** A `LawSystem` layer (two CSV tables, three state maps, one order `LAW_SET`) writes a decreed value and, as each courier arrives, a per-place in-force value; every other system reads a law only through `LawSystem`. The economy reads each province's in-force rates; military laws read per unit and pay through `LawEffects`.

**Tech Stack:** Godot 4.7, typed GDScript, GUT (`./run_tests.sh`, `--fast`), CSV data under `data/`.

**Spec:** `docs/superpowers/specs/2026-10-08-laws-tab-design.md` — read it before any task. §n below means the spec's section.

## Plan rulings (where the plan settles what the spec leaves open)

- **R1 — values are Strings.** A law's value is stored as a String in every state map ("on"/"off", a choice's name, a range's digits). `LawSystem.number` gives a range's int.
- **R2 — `laws.csv` has no `admin_cost`.** The `admin_cost` column of the policy tables is read by no script; laws add `cost_ops` instead: the op grammar `EventEffects.apply` already speaks (`opinion:steward:-2:re-cutting the tax rolls`), charged when the order executes. `gold_cost` stays (extra gold on top of the order row).
- **R3 — `LAW_SET` has one `order_costs` row** (`gold:-1:the chancery drafts the decree`, `always=1`) so invariant 8 holds; the per-law gold and ops come from `laws.csv`.
- **R4 — cooldown is per law**: `state.law_cooldown[law] = tick until which it is on cooldown`. The `LAW_SET` row in `policy_actions_court_additions.csv` has `cooldown_ticks` 0.
- **R5 — re-sending.** Spec §3 says a value must differ from the decreed one, and §5 says a place whose courier was lost may be decreed again. Both hold: a decree whose value equals the decreed one is allowed while `LawSystem.delivery(...).missing` is not empty, and then sends couriers ONLY to the missing places, with the SAME `decree_id`.
- **R6 — a courier to a place** (province or town) has `target` = the scope key (`province:<code>` / `town:<code>`), never a unit code. `CourierSystem` must not call it lost (it is exempt like a spy, §3.3 of the survey) and never re-aims it. A courier to a unit has `target` = the unit code (re-aimed for free).
- **R7 — three old settings keep their modes as choices:** grain policy `market|ration|release` (default `market`; `release` acts as `market` for the court ration and pays its one-shot on delivery), church policy `none|endow|tithe` (default `none`), justice severity as a range. A one-shot is paid when the value CHANGES to it; to pay it again the value must first change.
- **R8 — `LawSystem.value` falls back** to `state.metrics` (`tax_rate`, `tariff_rate`, `grain_ration`) when the law state is empty (a hand-built test state with no law tables), so the older fixtures that set `metrics` still work.
- **R9 — no `SAVE_VERSION` bump.** The three new maps default empty; `LawSystem.ensure` seeds them at load.
- **R10 — law couriers use `ordinary`.** No new courier kind (it would need courier art rows).
- **R11 — `law_effects.csv` gains columns** `timing` (`monthly`|`once`) and `share` (`army`|`people`|`unit`|`flat`), and a once-row of a range law is per point of change. Columns: `law_code,value,channel,target,amount,timing,share,reason`.
- **R13 — an annexed province** (no in-force entry) reads the law's default until a courier reaches it.
- **R12 — state keys.** `state.law_decree`, `state.law_in_force`, `state.law_cooldown`, written plain (`_encode_values` handles nested ints).

## Review Focus

- A province taken by another kingdom while its law courier rides: the courier is dropped as lost, nothing is written for the foreign province (Task 2 test `test_a_courier_to_a_lost_province_is_dropped`).
- A decree whose recipients are empty (no province held, no unit): the order is refused with a reason, not accepted with zero couriers (Task 2).
- A unit settling into a camp whose law state is newer, and leaving it again, keeps the higher decree per law (Task 6).
- An older save with no law state loads and behaves as the metrics said (Task 1 `test_an_older_save_is_seeded_from_the_metrics`).
- The monthly nudges of the military laws against the 0.2-a-month pull of contentment, legitimacy and church toward 50: a law's net effect over a year must be visible (Task 6 test pins the net over twelve months).
- A typed order naming a law or value that does not exist is rejected with the validator's reason, never reaches `execute` (Task 3).
