**Goal:** Make saved physical battle groups inspectable through the actual player 3D map, then complete N0's visual gate before N0 merges.

**Architecture:** Add one read-only battle-group mode to `Map3DLayerUnits`, using the existing models, world conversion, visibility and snapshot runner. **Tech Stack:** Godot 4.7 Forward+, typed GDScript, existing Terrain3D/player map and model scenes, SuiteData/GUT, real-window snapshots and visual-review contact sheets.

**Spec:** `docs/superpowers/specs/2026-10-17-unit-behavior-and-battlefield-design.md` §6–8, §14; accepted `docs/superpowers/plans/2026-10-23-p4-narrow-deployment-reserves.md` N0. ## Global Constraints

- “3D兵人按真实可战人数显示，每50人一个，不满50人向上取整；伤兵、俘虏不显示、不参战。WAR ROOM每支实际单位只有一个棋子，不随人数增加数量或体积。” This step applies the 50-person rule to active saved battlefield groups; outside-battle tier replacement remains outside this bounded fix and must not be claimed complete.
- “当前可见敌方实际单位按真实可战人数显示” is permission for currently visible foes only. Ghosts use their existing last-known presentation, never live groups, counts, facing or losses.
- “战略单位位置、部署组的整数世界位置及其占地同属一份模拟事实”. Rendering never refreshes groups, changes anchors, calls deployment/march, advances time, chooses contact or writes casualties.
- “所有调校数值进入data，静态外观通过编辑器资源制作”. Reuse existing group spacing/depth data and Units inspector exports; no new art, geometry constants, scene/material text edits or new 2D map.
- Existing map signals, unit selection/orders, march routes and WAR ROOM retain unit identity. Group figures are children of one unit, never additional roster units, orders or WAR ROOM pieces.
- Real-window shots only; headless tests prove arithmetic/state, not Terrain3D appearance. No available gdai MCP means any necessary static resource change stays blocked until an authorized local editor pass; no text-edit fallback.

## Review Focus

1. Hidden enemy / ghost: altering live enemy groups must not alter any hidden or ghost draw, per-unit geometry digest or permitted-row export; whole-save provenance hashes necessarily change (G1 visibility tests).
2. Paused same-day change: groups/facing can change without the regiment/day changing; refresh must update nodes without a camera pan (G1 cache tests).
3. Legacy / bad rows: absent groups may use the existing unit fallback, but corrupt or mismatched present rows cannot masquerade as verified physical geometry (G1 input tests and capture failure).
4. Scale / terrain: giant existing miniatures, tilted parents and interpolation must not move a group's world XZ away from its saved point (G1 transform and footprint tests, real near/far shots).
5. Lifecycle: 101→100, merge, reload and unit removal must remove stale nodes without creating people or making the renderer a simulation writer (G1 lifecycle tests; N0's original pair proves continuity).

- Consumes `Map3DContext.regiments() -> Array`, `.ghosts() -> Array`, `.state() -> GameState`, `.to_world(pack_px: Vector2) -> Vector2`, `.height_at(xz: Vector2) -> float`; `BattleSystem.battle_of(state, code) -> Dictionary`; `ArmySystem.metres_to_pack(repo, metres: Vector2i) -> Vector2`; `WarFront.facing_vector(degrees: int) -> Vector2` and `Map3DUnits.facing_yaw(heading: Vector2, stand_deg: float = 0.0) -> float`.
- `Map3DBattleGroups.sample(ctx: Map3DContext, code: String) -> Dictionary` (static) returns `{mode:String, rows:Array, facing_deg:int, key:Array, error:String}`. Modes: `groups` (including valid zero fit/zero rows), `fallback` (not in battle or absent legacy groups), `invalid` (present malformed/mismatched rows). `rows` copies only `{slot:int, count:int, role:String, x_m:int, y_m:int}` for that admitted real code. Missing legacy slots use array indices in the view only. `key` contains the copied visible facts; it never hashes/exports a hidden battle wholesale.
- `Map3DBattleGroups.build(repo: DataRepository, reg: Dictionary, sample: Dictionary) -> Dictionary` (static) produces one existing-style unit piece dictionary: aggregate `node:Node3D`, flattened `anims:Array`, `height_m`, `extent`, `figures`, `layout:"physical_groups"`, `groups:Array` (each `{slot, count, role, x_m, y_m, piece:Dictionary}`) and `sample_key:Array`. Each group's `piece` is built with one origin figure through `Map3DFormation.of_regiment`, retaining its measured model metadata/clips. No model or no fit people creates no phantom figure.
- `Map3DBattleGroups.place(ctx: Map3DContext, piece: Dictionary, selected: bool, gap: float) -> void` (static) places each child from the stored sample, seats it, and applies the existing selection glow. Parent uses unit anchor translation only (no rotation/scale); children use their own measured poses. `gap` is the existing Units `formation_gap`.
- `Map3DBattleGroups.evidence(piece: Dictionary) -> Array` (static) reads actual group node global positions/yaws/scales plus source `{slot,count,role,x_m,y_m}`; it must not merely call `sample` again and label that a measured draw. Returns JSON-safe numeric arrays with `xz_world`, `yaw_rad`, `scale`, and projected model bounds measured during `place`; developer artifacts may contain exact sampled row counts for checking, but no new player count labels/card fields are added. Export contains no contact, health, losses, reserve strength or other private battle fields.

**Coordinate and size contract (not an alternative layout):**

For each saved point `m = Vector2i(x_m,y_m)`, `px = ArmySystem.metres_to_pack(repo,m)` and `xz = ctx.to_world(px)`. Thus `xz = pack_origin + Vector2(m) / ArmySystem.metres_per_pack_px(repo) * meta.m_per_px`. Do not treat engine metres as built metres or multiply model offsets by the unit's miniature scale. For metadata `{pack_origin:[-100,50],m_per_px:2}` and synthetic `repo.map_info` distance_unit `km`, distance_scale `0.01` (10 metres/pack-pixel), `(200,300)` maps to `(-60,110)`, `(230,340)` to `(-54,118)`: delta `(6,8)`, not `(30,40)`.

Facing uses saved whole-degree `group_facing[code]`, not camera direction, anchor-to-enemy recomputation or the regiment's smoothed march heading. Convert through `WarFront.facing_vector` and `Map3DUnits.facing_yaw`; pass the model's `stand_deg` with its current semantics: `yaw_for` applies it only for a zero heading, so a saved facing vector receives no extra stand-angle correction. Test 0/90/180/270 and a noncardinal angle, including a model with nonzero `stand_deg`, against the actual helper result. N0 currently stores facing per unit, not per row; do not invent saved group-facing fields. No rotation of saved position offsets when facing alone changes.

Cap the old camera-reference figure scale by the existing physical group pitch: transform `battle_group_spacing_m` and `battle_group_depth_m` to built world metres; each model's full measured footprint times `k * gap` must fit those pitches. Choose the minimum of the old scale and those two footprint bounds. For synthetic built pitches `(8,12)`, model half extents `(0.5,1.5)`, gap `2` and old scale `10`, the cap is `min(10,4,2) = 2`. These are hand-test values, not approved art tuning. Do not move saved centres to accommodate an oversized model, recalculate simulation clearance from art, or change people-per-figure. Reuse the model's seat clearance/sink and yaw correction. Keep group roots upright at exact saved XZ while seating vertically on sampled terrain; whole-unit slope tilt, interpolation, lag, turn easing and the ordinary unit march forecast must never rotate/translate a physical group cloud. Existing animation clips still run through the informed `_battle.action_for` path with stable unit/slot phase keys; animation cannot change group root XZ. This bounded renderer does not claim new walking/contact/death choreography.
