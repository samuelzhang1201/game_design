# Game data (`data/`)

- **Design values live here, never hardcoded in scripts.** Add columns or rows rather than embedding a constant.

## The scene folders (spec `2026-10-11-data-folders-by-scene-design.md`)

The tables are sorted by the part of the game they tune, so a balance pass opens one folder. `tables.csv` (`folder,table`) is the index: code reaches a table through `DataRepository.table_path(dir, table)` (Python: `tools/data_index.py`), and a literal path (a `const`, a default argument, a comment) must be the indexed one.

| Folder | Holds |
|---|---|
| `realm/` | laws and their effects, domain policies, order costs, action signatures, metric polarity, the world schema |
| `ledger/` | the LEDGER's model: object and link types, static nodes and links, loops, clusters, governance, actions |
| `council/` | seats, the founding council, roles, traits, relationships, faction escalation, court policies, line templates; the model caps (`prompt_*`, `order_*`, `tone_delta_cap`) |
| `economy/` | manors (buildings, estates, focus), building inputs, goods, workshops, road speed |
| `army/` | every `army_*` table, foraging and desertion words, march hazards, war plan kinds and order words, war works; the war sheet's rules and royal movement |
| `battle/` | battle outcomes and stances, the enemy's doctrines; sieges and raids |
| `intel/` | spies, couriers, intel facts, facts, claim types, world rules |
| `story/` | random events and choices, the prologue's events, choices and branches, presenters, locations, regions |
| `world/` | weather and its odds, landmark names, marker types, `maps.csv` |
| `screens/ui/`, `screens/map3d/`, `screens/war_room/`, `screens/ledger/` | the LOOK only — palettes, fonts, the title, the 3D map's bake, houses, trees and pieces, the WAR ROOM's marks and folio, the LEDGER's lenses; nothing here changes an outcome |

- **Each indexed folder's `balance.csv`** (`key,value,notes`) holds the numbers of what that folder tunes; `DataRepository.load_balance` merges them into the one `balance` dict read by `bal()`, and a key in two files fails the load naming both. A new number goes into the folder of the thing it tunes; a number only a screen reads goes under `screens/<screen>/`. Each folder with a balance file must have at least one table row in `tables.csv`.
- **Guards** (`tests/engine/test_data_layout.gd`): the index and the disk agree, no key repeats, the engine reads no `screens/` key but the named look-helper keys (`ENGINE_LOOK_KEYS`), and no code or guide names a table by a path the index does not give.
- WAR ROOM tables: `war_marks` / `war_mark_hazards` (the marks the WAR ROOM inks and the two that take a share of a supply line), `hazard_kinds` (what each pack zone type does as a hazard — its months, whether it is public, its toll and its ink), `war_works` (the strategic goods that make a town a war works on the sheet, by family and glyph).
- Army supply tables: `army_carry_loads.csv` (carried-load days → march pace), `army_supply_orders.csv` (the supply rows of the regiment menu), `army_hostile_stances.csv` (stances whose regiments cut supply lines).
- Battle and enemy-AI tables (spec `2026-10-07-enemy-ai-and-battle-design`): `battle_outcomes.csv` (the five result tiers tiling eff 0..1000), `battle_stances.csv` (hold / steady / evade), `ai_doctrines.csv` (one row per host role), and the pack's hand-maintained `military/raid_hosts.csv` (the raider realm's hosts: PACK regiment codes joined by `|`, each raising the units split from it, `EnemyAi.host_units`; `appear_day`, `role`, start in pack coordinates); the `battle_*`, `ai_*`, `siege_*` and `raid_*` keys in `battle/balance.csv`.
- **The army's split tables** (spec `2026-10-07-army-split-and-ground-design.md`): `army_split.csv` (the arms in split order, each one's first camp ring, the pooled royal train) and `army_camp_blocked.csv` (the terrain no unit camps on), with the `army/balance.csv` keys `army_split_cap_men`, `army_slot_spacing_m` and `army_slot_max_rings`. `army_scouting.csv` (spec `2026-10-14-unit-clearance-and-scouting-design`: per arm the `scout_km` and `arc_deg` of a marching unit's scouting sector, `DataRepository.army_scouting`) `army_clearance.csv` (per arm the clearance radius in metres, sized to the drawn piece: two units stand at least the sum of their radii apart) and the keys `army_clearance_on` (0 turns the rule off), `army_clearance_touch_m`, `army_spread_reach_m` (a host column near its target takes a camp slot round it; the siege counts it as at the town) and `army_slot_spacing_m` (at least twice the largest radius) with `intel/balance.csv` `scout_report_gap_days` and `missive_keep_scout`. The pack's `military/regiments.csv` is the split's INPUT, not the live army: the army is `GameState.army_roster`, read through `ArmySystem.roster`.
- **The laws** (spec `2026-10-08-laws-tab-design.md`; rules in `scripts/engine/CLAUDE.md` "Laws"): `laws.csv` (a row per law: page, group key, label, kind toggle / choice / range, values, default — the first value of a toggle or choice — scope province / camp, `gold_cost`, `cooldown_ticks`, `cost_ops` in the `EventEffects` op grammar), `law_effects.csv` (`law_code,value,channel,target,amount,timing,share,reason`: `timing` monthly / once, `share` army / people / unit / flat; a blank value on a range law's once-row means per point of change; `amount` a number or a `balance.csv` key, `-key` negated; a reason on every row) and `law_words.csv` (`key,text`: the screen's page and group titles, value labels, phrases, refusal words). `missive_keep_law` is the count of a decree's letters kept apart from a column's. There are 25 laws (17 military); a `dev_renaissance` / `dev_chivalry` channel row (`share=flat`, monthly) is a development-axis drift read by `DevelopmentSystem.law_drift`, never written to a metric. `realm/honour_bound_options.csv` (`law_code,value,notes`; loaded as `repo.honour_bound_options`: the law options a realm at the `honour_bound` development flag may not decree, `LawSystem.refusal_of`). `conduct_words.csv` (`key,text`, loaded as `repo.conduct_words`) holds the Marshal's-report letter, folio, slip and ink words of foraging and desertion (spec `2026-10-10-foraging-and-desertion-design.md`; rules in `scripts/engine/guide/foraging_and_desertion.md`); their numbers are the `army/balance.csv` `forage_*` and `desert_*` keys. `LAW_SET` has one `order_costs.csv` row; its `action_signatures.csv` variants are `law=<code>&value=<v>` or, for a range, `law=<code>&delta_pos` / `&delta_neg`.
- `title_entrance.csv` (`node,kind,delay_ms,duration_ms,lift_px,ease,step_ms`, loaded as `repo.title_entrance`): the title's entrance after the black of launch, in order — `curtain` (the black lifting), `fade`, `lift`, `ripple` (each shown child, `step_ms` apart), `rise` (a name line up out of its clip, `lift_px` per cent of its height); ease `expo` or `quart`.
- **The exception is the LOOK**: art references and styling are resources and scenes edited in the Godot editor — never a `res://` path column here (a key → art table is an `ArtTable` `.tres`; the CSV keeps only the key's numbers and words).
- `data/` carries a `.gdignore` at its root so Godot does not import the tables as translations; `FileAccess` reads them regardless. `game_story/` carries one for the same reason. A future export preset must include `data/**` AND `game_story/**` explicitly.

## Map packs

- `army/commanders.csv` declares named military eligibility (`character_id`, realm slot, eligible flag, allowed unit kinds, portrait key, reserve priority); full character and family facts remain in `council/roles.csv`. Eligibility is separate from the character's display category. The engine excludes the king, conflicting council offices and unfit personnel at enlistment/appointment.

- `data/world/maps.csv` has one row per pack (its bitmaps, its data dir, `is_default`, `map3d_dir`); no code, tool or test names a pack (`DataRepository.default_pack_id()`, `DataRepository.map3d_dir`, `tools/packs.py`). Bringing in a new pack: `tools/NEW_MAP.md`. `data/maps/` is the packs' own tree, outside the index.
- `data/maps/<id>/` at its root: `map_info.csv` (incl. `distance_scale` / `distance_unit` and the graticule `lat_n` / `lat_s` / `lon_w` / `lon_e`) and the HAND-MAINTAINED bindings, never written by the importer — `realm_bindings.csv` (authored realm slots → kingdoms), `house_bindings.csv` (the court's families → provinces of the player's realm; unbound provinces are held by a house named after their seat), and the optional `manor_name_overrides.csv`, `arms_bindings.csv`, `landmark_name_overrides.csv`. Only realm slots with an authored palette entry claim fixed colours; structural-only bindings retain the `other_N` colours in state order.
- Imported by domain: `geography/` (`biomes`, `cells`, `vertices`, `coasts`, `rivers`, `markers`, `routes`, and the BAKED `march_grid.png` — 8-bit grey, lossless, one pixel per `army_march_grid_px`: steepest rise per run in hundredths, 255 water — written by `tools/map3d/bake_march_grid.py` from the 3D build's heights, never hand-edited, read by `MarchPath` without an import), `political/` (`kingdoms`, `provinces`, `burgs`, `manors`, `borders`, `province_borders`, `diplomacy`, `campaigns`), `economy/` (`kingdoms`, `provinces`, `burgs`, `goods`, `markets`, `market_goods`, `production`, `deals` — the export's trade flows, loaded as `DataRepository.deals` and read by `MarketSystem`), `military/` (`kingdoms`, `regiments`, `unit_types`), `society/` (`cultures`, `religions`, `zones`).
- The pack's bitmaps are in `assets/maps/<id>/` and are DATA: every `world_*.png` is imported lossless, never VRAM compressed (it scrambles manor ids and bands the sea; `project.godot`'s `[importer_defaults] texture` carries `detect_3d/compress_to: 0` for that reason). They are generated (`tools/import_azgaar.gd` and the bakes) — a lasting change belongs in Azgaar, never a hand edit; `tests/map3d/test_map3d_look_assets.gd` fails if one loses `compress/mode=0` or the detect-3D flag.

- **Development axes** (spec `2026-10-12-development-axes-design.md`): `realm/development_axes.csv` (`axis,tier,min_score,hysteresis,label`: tiers 0..3 per axis, `min_score` strictly rising, loaded as `repo.development_axes`) and `realm/development_tier_effects.csv` (`axis,tier,channel,target,amount,timing,reason`: a metric channel is `monthly`; `arm_power_permille`, `cavalry_upkeep_permille`, `adopt_permille`, `flag`, `unlock` are `permanent`; `amount` a number or a `balance.csv` key, `-key` negated, as `LawEffects.amount_of`; loaded as `repo.development_tier_effects`). `character_traits.csv` carries `dev_renaissance` / `dev_chivalry` (ints, -100..100) as a ruler's preference; the `dev_*` keys in `realm/balance.csv` hold the start scores, decay, AI step and target, decree opinion and cavalry upkeep.
