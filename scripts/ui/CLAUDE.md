# Screens and HUD (`scripts/ui/`)

Root rules first: invariant 10 (the columns divide by kind), the look lives in the editor, every visual change through the `visual-review` skill. Screens are self-contained scenes signalling up to GameRoot; state changes only via `Game`. Specs: `2026-10-01-war-table-ui-design.md`, `docs/superpowers/plans/2026-10-02-editor-native-ui-pilot.md` and the per-feature ones.

## The look lives in the editor

- A converted screen's static look AND layout are its `.tscn` and `.tres`: columns, map, compass and seal stand where the scene puts them. Opening the council column only brings the map's right edge in to the screen's exported `council_gap` (`ScreenLayout.open_right`); `ScreenLayout.apply` / `place_handle` lay out only the leather chrome (`ui_war_table` 0) and unconverted screens.
- **The game's Theme** is `assets/2D/ui/theme/game_theme.tres` (`project.godot` `gui/theme/custom`; `UiPalette.build_theme()` returns it); `assets/2D/ui/theme/paper_theme.tres` is the paper column's and the WAR ROOM slips'. Role fonts are `assets/fonts/roles/*.tres`. Panel looks are StyleBox `.tres`: `assets/2D/ui/war_table/styles/`, the leather `assets/2D/ui/panels/styles/`. Custom styles and drawn pieces are `@tool` with exports (`PaperStyle`, `BrassStyle`, `BoardStyle`, `VellumPanelStyle`, `RibbonStyle`, `ScaledNineSlice`, `WarTableBackdrop`, `BrassDial`, `TableCompass`, `WaxSeal`, `SpeechBubble`, `ResourceIcon`, `HeraldicShield`, `TitleShade`). Key → art tables are typed Resources: `ResourceIconSet` (`resource_icons.tres`) and the `ArtTable`s named in `GameArt` — army paintings and 3D models, couriers' paintings and models, `estate_paintings.tres`, `goods_marks.tres`, `goods_icons.tres`, the house types' meshes.
- In the editor the `Game` autoload is a placeholder: `UiPalette.data()` is the one way the look reads tables (`DataRepository.load_look` in the editor). A scene's properties are set BEFORE its script, so a `@tool` `_init` only fills a property still at its engine default. A shared look resource a screen CHANGES at runtime is `resource_local_to_scene` (`report_paper.tres`).
- **Cards write in THEME KINDS, never colours**: `CardTitle`, `CardLabel`, `CardText`, `CardHint`, `CardTag`, `CardStatName`, `CardValue`, `CardFigure`, `CardGood`, `CardSmall`, `CardWarn`, `CardPlus`, `CardSection`, buttons `CardCommand` / `CardCommandSmall` / `CardRow` / `CardCross` / `CardMenu`; `Dash*` for the realm card, `ManorTable` (on the paper report faint ink on paper, its header a ruled line), `Folio*`, `MissiveLetter*` / `MissiveFact` / `MissiveNote`, `TitleWord*`, `Bookmark`, `LogEntry`, `HeaderLabel` / `TitleLabel` / `SectionLabel`. Each theme writes them in its own ink: on paper `CardWarn` is the slip's rubric red at the figures' size, on leather a pale rose. A card fact with `tone` `warn` (`MapObjects._stat`: a broken or cut supply line) is written in `CardWarn`.
- What code still owns on a converted scene is written in the node's `editor_description` and listed with its reason in `tests/ui/test_editor_owned_look.gd`'s `CODE_OWNED` — the guard that fails when a converted script's `_ready` sets a look or a declared look property no longer holds after `_ready`. `_dress_leather` methods put the leather chrome on under `ui_war_table` 0.
- Authored in their scenes so far: `court.tscn`, `top_bar.tscn`, `conversation.tscn`, `main_menu.tscn`, `bottom_bar.tscn`, `news_ticker.tscn`, `map_detail_panel.tscn` (`MapDetailPanel.create()`), `country_panel.tscn`, `military_panel.tscn`, `manor_master_panel.tscn`, `realm_dashboard.tscn`, `missive_screen.tscn` / `missive_report_popup.tscn`, `laws_screen.tscn` / `law_row.tscn`, `war_table/council_seal.tscn`, the WAR ROOM's scenes. Every other screen still dresses itself in code until converted; `WarTable.ink_column` repaints the leather-ink overrides of unconverted cards; `WarTable.sheet_style()` / `report_style()` copy the scenes' `.tres` for pieces still made in code.

## Window size and the design viewport

- **The design viewport is 1280x720**, stretched with `canvas_items`; the game lays out in design px and draws at window resolution. When adding a number, three kinds are NOT design px: values already × `view_scale()` (`map_label_scale_px`), values in a texture's OWN pixels (`PANEL_ART_SOURCE_INSET`, `ResourceIcon`'s `u := s / 9.0` glyph grid), values in native map px (`PREVIEW_SPAN`). `tests/ui/test_display_fit.gd` pins the viewport.
- **It must look right at ANY window size**: `rendering/textures/canvas_textures/default_texture_filter` is Linear with mipmaps and every art `.import` generates mipmaps (the `*_index.png` hit-test bitmaps are data, the exception). Nearest is only crisp at an exact integer scale. Fonts need nothing. `tools/snapshot_screen.gd --resolution WxH` renders through the REAL window and is the only faithful check (`--scale` exercises a different path).
- An installed raster is sized by its USE: design px × the largest window scale (~3×), never one size for all.

## Theme, colour and type

- **A DARK theme after Crusader Kings III** for what is held up to the eye (the audience window, events, menus, popups, the council column): parchment ink on grained dark leather, gold accent and trim, sunk inputs (`UiPalette`; `tests/ui/test_ui_palette_dark.gd` pins contrast, not hexes). `UiPalette.panel_style(border, width, margin, kind)` returns a `VellumPanelStyle` with procedural leather grain; `kind` is `window`, `column` or `map`, and the vellum ornament marks only windows (`ui_panel_ornament`), a column wears a gold hairline instead. Section headers are `UiPalette.style_section`; empty bar tracks are sunk. `StyleBoxTexture` has no scale of its own, so a nine-sliced source PNG IS its drawn size (the vellum plate, `ui_panel_art` 0, is off).
- **Data colours are HERALDIC tinctures** (or, azure, vert, purpure, gules) in `chart_palette.csv` (`cat_*`, `sequential`, `skill_*`, `positive` / `negative` via `UiPalette.good_color` / `bad_color`); on the map, dark leather chips with parchment figures (`political_palette.csv`). Never web-dashboard blues and greens.
- **Fonts divide by job** (each role a `FontVariation` in `assets/fonts/roles/<role>.tres`; `data/screens/ui/ui_fonts.csv` keeps `size_scale` and `title_case`): **Crimson Pro** for everything read; **Alegreya SC** tracked small capitals for section headers, names, the date, tabs and the scale bar / ruler (`lnum` lining figures); **UnifrakturMaguntia** ONLY for titles and the kingdom names on the map. Apply them through `UiPalette.role_font`, `style_header`, `style_tab`, `style_title` (with `readable_title` for an ALL-CAPS title), `display_font` and `map_label_font`. `UiPalette._FALLBACK_FONTS` covers a missing role file. A RichTextLabel's ink is its own `default_color` (it does not inherit the Label colour).
- Every whole figure is grouped by thousands (`UiPalette.format_int` / `format_delta`).

## The war table (`ui_war_table` 1; `scripts/ui/war_table/`)

- The court and conversation screens lie on a pale oak table by daylight, every piece an object on it, one light upper left, every soft shadow down-right: the map a vellum sheet (`map_sheet.tres`), the left column the steward's pinned report (`report_paper.tres`, the paper turned by `tilt_deg` while the content never turns; drawn as tall as the realm's card, `WarTable.fit_report`), its cards in PAPER INK (`UiPalette.ink(role)`, `style_rubric` for the red ¶ headers, `BarChart.tally` for tally marks, the people and the host as sentences), the top bar a `BrassDial` with studs and a tally board, the bottom tabs silk bookmarks grouped by colour, the news a paper slip lying in the band between the two bookmark groups (`BottomBar.slip_band` → `NewsTicker.place_on_table`). What is held up to the eye stays dark leather. Code-drawn pieces take colours from `data/screens/ui/ui_table_palette.csv` and numbers from `ui_table_*` / `ui_paper_*` / `ui_seal_*`. `ui_war_table` 0 keeps the leather chrome untouched.
- **The compass is the map's own** (`CompassLayer`, inside the map sheet's top-left, `map_compass_size_px_table`); nothing lies on the table under the report, so the left column runs down to the screen's foot margin, clear of the bookmarks.
- **The council seal and row**: ENTER THE COUNCIL is a `WaxSeal` (a Button; its words only in the tooltip), `scenes/war_table/council_seal.tscn`, at the map's top-right corner; beside it THE WHOLE COUNCIL as round miniatures in seat order running leftward along the map's top edge. Those with a matter — this month's report's speakers (`ConversationBeats.waiting`) and the presenter of a waiting event — are ringed in gold with a drop of wax, the others dimmed while anyone waits, until heard (`WaxSeal.hear`). A cream SPEECH BUBBLE rises slowly under the first marked ("A matter to report, Majesty."), and a click on it is a click on them. Seal click → `council_requested`; miniature click → `councillor_chosen` (on the court an AUDIENCE with that councillor alone, `GameRoot.audience_with`; on the conversation stage `ConversationScene.seek`).
- **Events wait on the table**: the opening narration (`OpeningNarration`: pages in `game_story/chapter_0/game_start.md`, a `## left|right` heading each, left = Lord Malvern, right = the king; one topic a page, no scrolling, capped by `opening_segment_max_chars`, in a window `ui_narration_window_h` tall on every page (`ConversationScene._fit_audience`); the busts are `ConversationScene.narration_left/right` inside `narration_left_frame/right_frame`, shown only while it plays and BOTH lit (`narration_dim` white by default); its lone Continue button is not lettered, only choices are) plays alone, a Continue turning each page, then the table is laid and the first event waits as its presenter's matter. At the month's end GameRoot stays on its screen and the clock runs on; a loaded save with a decision pending resumes on the court; the news names who waits once a month (`_announce_waiting_matter`) and a new event raises the bubble (`nudge`). On the war table the top bar's EVENT chip is not shown.

## The audience window and the cards

- **The left column** (root invariant 10): each screen owns one `_refresh_left()` applying the precedence card > hovered country > host > the column's own content; no panel hides its siblings, and nothing in it widens `ScreenLayout.LEFT_WIDTH` (wrap and scroll).
- **The audience window** (`event_popup()` is it) is centred over the map (`%AudienceLayer` on the map panel, faintly dimming it): the person on the left (portrait cut head to waist before the room, `AudienceBackdrop`, or a `data/story/locations.csv` `backdrop` painting; name plate with arms, seat, opinion whose tooltip lists its last reasons (`CharacterPortrait.opinion_summary`), trait chips, five skill badges), on the right this beat's exchange (the record keeps every beat once it has passed), BIO / SKILLS / TIES pages, the options (trade-off and cost on hover) and the talk box. Only the MOVE list keeps the small popup.
- **Foraging and desertion lines** (words `conduct_words.csv`): the unit card appends `WarFolio.conduct_rows` (a "Foraging" row, a "Deserted" row when non-zero) to its `fields`, and the supply tooltip separately repeats the foraging state and the kingdom card a "Grievance" line only above 0 (`MapObjects`); rules in `scripts/engine/guide/foraging_and_desertion.md`.
- **The manor card** (`MapDetailPanel`, its map window `TerrainPreview`): `MapObjects.manor_card` gives `stats` (`{key, text, tooltip}`, the key a `resource_icons.csv` `manor_*` row) and `rates` (every good it makes a month); `fields` stays for tools and tests and non-manor cards render it. The estate's painting pinned above the scrolling body as a band at most a quarter of the card (`MapDetailPanel._fit_painting`); facts named as rows — art, `resource_icons.csv` label, value right-aligned — under the sections of `data/screens/ui/manor_card_sections.csv` (`ui_manor_card_rows`; `MapDetailPanel._fill_stat_rows`), the month's output rows from `ManorEconomy.line_of`. BUILD is ONE dropdown (`_add_build_menu`, `fit_to_longest_item` off), each entry its art, cost, days and a tooltip of its yield, a building blocked by a predecessor disabled with why; standing buildings fill slots, a work in progress is a dashed see-through box. A card with a painting skips the map window; the map window's width is flexible (only its height is fixed).
- **Dimension icons are game art** (`assets/2D/icons/resources/`, named in `resource_icons.tres`): `ResourceIcon` draws the art when the key has some, else the gold glyph; `BarChart` / `PieChart` rows with a `dimension` draw the art with the label as tooltip, or named gauges (`ui_dimension_labels`, `BarChart.named`). Words stay only where the row is a name.
- **Arms** are worn by the top bar, the map detail card (`MapDetailPanel.house_of_card`), Manor Master rows and the audience name plate (`HeraldicShield.set_texture`, falling back to a coloured shield with an initial).

## Bars, menus and screens

- **The top bar** holds only the two purses (the Crown and the house's arms rows, laid out in `scenes/hud/top_bar.tscn`, changes written `+1,597/mo`) and the clock; unrest, legitimacy, drill and the church are on the player's country card.
- **The bottom bar** (`BottomBar.TABS`): the map's lenses left (`MAP_TABS`: HEIGHTS, MANORS), the screens right (FAMILIES, LAWS, RELIGION, MISSIVE with its unread count, WAR ROOM, LEDGER), each a word with a gold underline when lit (`UiPalette.flat_tab`), groups coloured as bookmarks on the war table. The regiments are always on the map; THE HOST opens in the left column from a regiment card.
- **The news bar** (`NewsTicker`): crawls only while the clock runs, keeps every headline dated (LOG opens the history), says so when no news has come; GameRoot announces works at `news_build_milestone_1` / `_2`, completions, the month's close, waiting matters, a courier setting out, a supply line broken because its town lies ahead of the column and flowing again (`SupplyLines.news`). Courier events reach it through `CourierSystem.news`, which says a decree's couriers as ONE line when they set out and ONE when the decree has reached everywhere it can (never one line a courier).
- **The title and the pause menu are one menu**: the same rows and settings (Music, Graphics, Frame rate, FPS, Dev mode — `GameRoot.settings_buttons`) and Quit to Desktop. Frame rate is `FrameCap` (`Engine.max_fps`, cycling `ui_frame_cap_choice_*`, first run `ui_frame_cap_default`, `settings.cfg` `[graphics] frame_cap`; forced off in the suite, benches and snapshots via `FrameCap.forced`). Space pauses/resumes play (`GameRoot._input`, `Game.toggle_clock`). FPS (`FpsToggle`) shows the frame counter (`FpsCounter`) whatever DEV MODE says: `GameRoot.set_show_fps` / `settings.cfg` `[graphics] show_fps`, off on a first run (never in a snapshot). DEV MODE is `GameRoot.set_dev_mode` / `settings.cfg` `[game] dev_mode`.
- **The title is THE LIVING REALM** (`TitleRealm`): the title's words over a live 3D map of the home province from its own preview `GameState` (`ui_title_seed`, never `Game.state`), no HUD or picking, camera drifting (`ui_title_*`). Take the Throne and Continue the Chronicle both sweep down to the opening view (`TitleRealm.sweep`); Continue reads the save first and stays if it is missing. The title HANDS ITS LIVE VIEW to the first screen (`TitleRealm.hand_over` / `take_handed`, `Map3DView.attach`'s `given`) and `TableLanding` lays it on the table like a sheet while every other piece comes from its own side (`ui_landing_*`), holding input while it plays. Its look is a cinematic hero (`main_menu.tscn`): three falls of `TitleShade`, top left the crown's arms and house (`TitleGlass`), top right the settings rows and Quit as `TitleNav` words in a `TitleNavPill` and the Music row as the speaker (`Sound`, the row itself hidden), bottom left the tagline, the name in light Crimson Pro (`TitleHeadline`, each line in its own clip), the lede and Take the Throne as a `TitlePill` beside Continue the Chronicle as a `TitleLink`, bottom right the place; `MainMenu.row(name)` finds any row. Without a built world the scene's Backdrop, the bare oak table, stands behind the same words. **Launch is a short black, then the title over the turning capital**: `GameRoot._ready` first asks `BootLoads` to read the world (`Map3DWorldLoader.request`), the `GameArt` model tables and the overlay and first-screen panel scenes on worker threads; the scene's `Curtain` holds the window black, the living map is made after `ui_title_reveal_frames` frames and `BootLoads.title_ready()` and opened a step a frame (`Map3DView.load_step`), then the black lifts and the words come in by `data/screens/ui/title_entrance.csv` (`MainMenu._enter`; `ui_title_failsafe_s` enters over the table if the map is slow); until then (`MainMenu.realm_pending`) Start goes in without the sweep. `GameRoot` shows the title a frame after the black and makes its ten overlays one per process frame (`OVERLAY_STEPS`, `overlays_ready`; a scene still on its worker thread is waited for in frames), so the black's turning `LoadWheel` (`@tool` TextureRect, the compass art at `map_compass_turn_deg_per_s`, `scenes/hud/load_wheel.tscn`) keeps moving; the suite and tools set `GameRoot.stepwise_overlays = false` and find every overlay made at once, and a Start or Continue clicked before they are made waits for them under Start's `_beginning` guard (a second Start or Continue meanwhile is ignored). The title's preview `GameState.new_campaign` stays in one ~0.27 s launch frame (engine static caches make a worker-thread build unsafe). Start makes the reign and its opening month in one frame and lays the first screen (the title's `hand_over` then `_switch_to`) in the next; a second Start meanwhile is ignored.
- **The Missive board** (`MissiveScreen`: four columns and a reading desk with Show on map): carved frame over real wood, every note an aged slip `MissiveScreen.NOTE_WIDTH` wide (the one on the desk ruled in gold), styles in `assets/2D/ui/missive_board/styles/` derived by `tools/missive_board_art.py`. A spy's report stops the clock and seals into a flying envelope (`MissiveReportPopup`, `EnvelopeFlight`); an audit letter's button opens the LEDGER on its flow (`GameRoot._open_ledger_on`). A reported figure is "≈ lo–hi" in its column's colour with the source tag small beneath.
- **The laws screen** (`LawsScreen`, `scenes/screens/laws_screen.tscn`; a row a law is `LawRow`, `scenes/panels/law_row.tscn`): LAWS in the bottom bar toggles it over the map (`GameRoot.toggle_laws`); it does NOT hold the clock. Three pages (economy, politics, military, the military rows under their `laws.csv` group titles); a row shows the decreed value, its delivery (`LawSystem.delivery`), the chosen value's effects (`LawEffects.summary`), one drop-down of the law's values (an `OptionButton` for every kind: a toggle's two, a choice's names, a range's levels) and the preview's cost or refusal (`LawSystem.preview`, cached per row); Decree and Send again give `LAW_SET` through `Game.try_execute` (only a refusal is said in the news from here: the decree's couriers say it); Places lists `LawSystem.untold`. Every word is `law_words.csv`'s; the screen computes nothing. Esc closes it, unless the pause menu or a spy's report stands above it (`above`: then Esc is theirs). Both scripts are in `tests/ui/test_editor_owned_look.gd`'s `SCRIPTS` and `test_the_laws_screen_keeps_its_scenes_look` holds both scenes (a row's drop-down popup wears `CardMenuPopup` from code: a popup is no scene node).
- **The LEDGER screen** (`LedgerScreen`) lies exactly over the map panel (the map stops rendering under it), holds the clock while open, reads `Ledger.galaxy` again after a state change (never twice a frame), puts a star's or thread's card in the left column and runs orders through `Game.try_execute` (an order that needs a place is Show on map). The view: `scripts/ledger3d/CLAUDE.md`.
- **The WAR ROOM screen** (`WarRoomScreen`, the one war-room piece that touches `Game`): `scripts/war_room/CLAUDE.md`.
- **Army menus offer only movement and supply**, never stance, garrison or seat buttons. Arrival and ground occupancy settle automatically; battle behaviour follows conditions and delivered royal orders. **Army orders** live here, not in `scripts/map3d/`: `ArmyOrderMenu` (`%ArmyOrders` in `court.tscn` and `conversation.tscn`), `SpyOrderMenu`, `LedgerOrderMenu`.
- **The march's confirm** (spec `2026-10-07-march-waypoints-design.md`, its rulings at the top): the regiment's menu offers no load; after the end is clicked `MarchConfirmPanel` (`scenes/panels/march_confirm_panel.tscn`, made once beside the menu) lists every `data/army/army_carry_loads.csv` load with `MarchPlan.carry_rows` (arrival, supplies, days they last, "runs N days short"), the current load pressed, then Confirm / Add waypoint / Cancel (`data/army/army_route_orders.csv`). It stands where it covers least of the route (`place_near`) and does not close on a click away, so the map can bend the route under it (`route_bent`, every waypoint checked by `validate_place`, a refusal put back). It also asks **Supply from** (spec `2026-10-08-war-room-draw-orders-design.md` rulings 13-15): the current town ("no change") or none first, then every realm town nearest the lead's column by road first (`SupplyLines.rear_order`), a town greyed with its reason unless it reaches the column now AND the march's end and lies not AHEAD of any selected unit, i.e. farther from the crown's capital than the column by more than `supply_ahead_km` whichever way it marches (`SupplyLines.march_eligibility`, `is_ahead`; ruling 20), pressed: the player's pick, else a draft's town, else the current town while it may serve, else the nearest allowed town; the towns are lit on the map (`supply_pick`), a click on a lit one chooses it, the chosen one's road to the end is drawn (`supply_preview`) and its figures written (`army_supply_orders.csv` `march_figures`). Confirm sends `SUPPLY_POINT_SET` (a new town only, at the line's rate else `supply_rate_default`), `SUPPLY_CARRY_SET` (only a changed load), then `ARMY_MARCH` with `waypoints`; in the WAR ROOM one draft holds them all. The WAR ROOM opens it through `ArmyOrderMenu.plan_group` (a blue arrow drawn for the selection: one row a regiment, a tick to leave one out, a refused one greyed; Add waypoint hidden). Edit route… loads the march's waypoints and end into the panel.
- **The old user:// directory** (`UserDirMigration`, called from `Game._ready`): the rename to "Beyond the King's Words" moved `user://`, so the save, key file and settings of the old "Crown and Council" directory are copied once through a `.part` temp file; never moved, never overwriting.
